## CON-UI-01: Product hierarchy and visual direction
- source: docs/final-mvp-ui-spec.md
- type: api-contract
- content: Primary question is "What do the historical grades look like, and are seats available?" A rate and seat availability are visible without opening details; historical grade ease is a secondary comparison aid; evidence scope and sample size travel with the numbers. Keep the existing deep green, warm paper background, dark ink, understated borders and typographic course headings. Green for available seats, amber for limited/stale evidence, neutral gray for unavailable data. Every status has a text label; color never carries meaning alone. Reuse existing type stacks and Tailwind tokens: readable sans-serif body and numeric labels, tabular numerals for rates/counts, existing display face for course headings. Body text normally 16px, supporting text no smaller than 12px, 8px spacing increments, 6-10px corner radii, consistent focus rings. No giant marketing hero. Required surfaces: search/results, linkable section details, methodology/data coverage, watch signup/confirmation, private watch management. Header navigation is Easy-A, Methodology, Manage alerts. Browsing needs no login.

## CON-UI-02: Search controls, sorting and URL state
- source: docs/final-mvp-ui-spec.md
- type: api-contract
- content: Show "USF Tampa" and the selected term. Use configured supported registration terms and a deliberate default from metadata; do not hard-code Spring 2027. Search accepts the existing course-code format with clear examples and normalized spacing/case. Keep subject, GenEd, modality and open-seats filters; secondary filters collapse on mobile. Sort options: historical grade ease, A rate, withdrawal rate, open seat count and course code. Default to grade ease descending with available evidence, followed by unscored sections without rank numbers. Nulls sort last for ascending and descending numeric sorts. Raw A-rate ordering must still show each row's sample size. "Open seats only" requires a fresh valid positive count and compatible source status. Persist selected term, search, filters, sort and page in the URL; restoring a link or using Back restores result position and filters. Keep server pagination, loading feedback, useful empty states and retry actions.

## CON-UI-03: Desktop results table groups
- source: docs/final-mvp-ui-spec.md
- type: api-contract
- content: Compact responsive table with these groups - Course/section (course code, short title, actual section number, CRN); Instructor (current name or Staff/unknown, with the verified RMP action in detail or a clearly labeled secondary link); A rate (prominent percentage or "Unavailable", plus `A of N A-F grades`); Historical grade ease (one decimal `/10` with methodology help, or "Insufficient data" instead of a number where required); Withdrawals (observed percentage, denominator explanation accessible on focus/click); Evidence ("This professor + course" or "Course only", N and term count, limited/insufficient label where needed); Seats/action (open/full/unknown/stale, count where valid, checked-at time, view details/watch action). Move long GenEd labels, policy lists and detailed enrollment breakdowns into details rather than widening the table. Use real header semantics and a table caption; sorting controls expose current direction.

## CON-UI-04: Mobile results cards
- source: docs/final-mvp-ui-spec.md
- type: api-contract
- content: Full-width section cards without horizontal page scrolling. Order: course/section and instructor; prominent A rate plus sample; secondary ease and W rate; evidence scope/terms; seats and checked-at; "View section" and "Email me when a seat opens". Avoid wrapping the entire card in a button when it contains links or other buttons. Do not show a subscribe action that pretends an already-open section is full - for an open section offer official registration and "Watch for a future opening" with explicit behavior. Unknown/stale sections may be watched, but explain that availability has not been confirmed. The card sample in the source is explicitly labeled illustrative; real values must come from the API.

## CON-UI-05: Section detail content order
- source: docs/final-mvp-ui-spec.md
- type: api-contract
- content: Linkable route keyed by term and CRN. A dedicated mobile page and a desktop page or drawer share the same content; a drawer must manage focus and preserve a usable direct URL. Order - (1) course title, term, actual section/CRN, instructor and supported schedule facts, with back-to-results preserving search state; (2) A-rate, historical-grade-ease and withdrawal summaries, each with its own state and short definition, explaining that W uses all recorded outcomes while A rate uses A-F only; (3) evidence summary with exact N and T, named semesters, section count, history scope and fallback reason, showing "Course-only history; not specific to this instructor" when applicable; (4) A-F distribution chart plus an always-available accessible table of grade, count and percentage, with W/I/S/U/O listed separately below and no chart drawn for absent counts; (5) seat panel with available count/state, capacity/enrollment if valid, waitlist availability separately, absolute and relative checked-at time, refresh status, monitoring cadence, official registration link and watch action; (6) policies as supported chips with current/historical badges, expanding to the exact evidence quote, named source term, professor/course scope and "Open syllabus" or "View schedule source", plus the syllabus link when no chip was extracted; (7) verified "View on Rate My Professors" action or a short unavailable label, with no ratings panel, stars, review cards or AI commentary; (8) compact supporting GenEd/modality facts and a link to the method/data coverage page. Evidence descriptions use ordinary language - replace student-facing "effective_n", "global prior" and "87% rule confidence" with understandable context.

## CON-UI-06: Methodology and data coverage page
- source: docs/final-mvp-ui-spec.md
- type: api-contract
- content: A permanent `/methodology` route accessible from the header and from score help. It explains what historical grade ease measures and the exact grade-only formula; A-rate and W-rate denominators including excluded/included grade categories; the small-sample adjustment, measured reference population, prior strength, minimum sample rules and method version/date; why an insufficient score can coexist with observed counts, seats or policy evidence; professor-course versus course-only evidence and the meaning of evidence-strength labels; how to read historical policy sources and checked-at seat observations; supported campus/registration terms, actual historical coverage and refresh cadence; and a worked example explicitly labeled synthetic. The headline formula and denominators cannot be hidden only in a repository README. State that historical outcomes do not guarantee an individual result and that seat observations do not guarantee registration eligibility or reserve a seat.

## CON-UI-07: Email watch screen states
- source: docs/final-mvp-ui-spec.md
- type: protocol
- content: Required screens and states - Signup (exact course, term, section/CRN, email field, one-alert behavior, cadence, "Send verification email"); Submitting (prevent duplicate submission, preserve input, show progress); Check email (monitoring activates after confirmation, rate-limited resend, change-email action); Confirmation (deliberate confirm action for the ownership token, clear active/expired/invalid/already-used result); Active (exact watched section, latest availability/check time, expected cadence, cancel action, how alerts stop after one email); Already open (say seats are currently reported, offer registration and an explicitly described future-opening watch); Completed ("Availability email sent" only after provider acceptance, current seats shown separately, offer rearm, do not claim inbox receipt); Manage link request (email field and a generic confirmation that does not reveal another person's subscriptions); Private management (all watches for the verified address, term/CRN, state, cancel/rearm and stop-all, no public watch lists); Unsubscribed/expired (clear outcome, no continued sending, optional new watch where registration is still supported); Service failure (useful retry copy, retain existing state, never show a successful subscription if creation failed). Expired ownership or management tokens offer a new-link flow. Avoid exposing credentials in page titles, analytics or referrer headers. Notification emails use the same clear identity, actual observed seat count/time, official registration and unsubscribe links. Escape all source-derived text.

## CON-UI-08: Required data and failure states
- source: docs/final-mvp-ui-spec.md
- type: protocol
- content: No course history - "Insufficient data" for ease, unavailable grade facts and a clear reason, while independently available seats/policies still work. Small observed sample - real rates/counts when permitted plus "Small sample: N A-F outcomes", ease unavailable below threshold. No measured reference - observed rates/counts remain, ease unavailable with an adjustment-reference explanation. W-only outcomes - A/distribution/ease unavailable, observed W rate and denominator remain visible. Suppressed or invalid source - explicit source limitation, no reconstructed counts or made-up percentages. No professor match - course-only history and reason, never imply a professor estimate. No current syllabus - clearly dated historical source if supported, otherwise no policy information. Missing RMP verification - "Verified RMP link unavailable", no guessed or search-result link. Full/over capacity - full status, no negative "available" badge, over-capacity detail only where source values validate it. Stale seat data - "Last known: 2 seats - Checked [time] - Update overdue", no green live-open badge. Unknown/cancelled seat state - plain unavailable/cancelled label, do not claim availability based on contradictory counts. API/source outage - existing valid cached facts only with age/status, error and retry feedback, never synthetic fallback. Empty search/unsupported term - scope-aware explanation and a useful filter reset or supported-term action.

## CON-UI-09: Interaction, accessibility and browser acceptance
- source: docs/final-mvp-ui-spec.md
- type: nfr
- content: Target 360px, 768px and 1440px layouts and 200% zoom. Approximately 44px touch targets, readable contrast, persistent visible keyboard focus and reduced-motion support. Tooltips work on focus/click, not hover alone. Input labels and validation errors are programmatically associated. Announce meaningful search/watch results without constantly announcing every seat poll. Charts require grade labels and the text table; neither color nor hover is necessary to understand them. Use safe external links and make opening a new tab predictable. Dialogs/drawers need focus containment, Escape handling and focus restoration. Avoid layout jumps when data loads; keep filters usable during background refresh and ignore outdated responses. Browser acceptance must demonstrate all five surfaces, all failure states, keyboard navigation, an actual frontend-to-API grade result, verified source links and the complete email management flow, with saved desktop/mobile screenshots for representative available, insufficient and stale cases. A generated design image, fixture-only page or passing component test is not a substitute for integrated browser verification.

## CON-CALC-01: Observed metric calculations
- source: docs/final-mvp-plan.md
- type: schema
- content: Let `N = A + B + C + D + F` and `T = A+B+C+D+F+I+S+U+W+O`, verified against the source Total Grades field. A rate = `100 * A / N`, displayed as "A grades among A-F outcomes" and `A of N`, excluding W/I/S/U/O, null when N is zero or counts are unusable. Distribution - each A-F bucket shows its observed integer count and `100 * bucket / N`, F included in the denominator, a text table accompanying the chart. Withdrawal rate = `100 * W / T`, displayed as `W of T recorded outcomes`, null when T is zero or invalid. Other outcomes - list W/I/S/U/O counts beneath the distribution. Sample wording is "recorded outcomes" or "A-F grades", not "unique students". Never average section percentages equally; sum eligible counts then calculate rates. Zero is a valid observed rate; null means unavailable. Round only for display. Use one explicitly selected historical cohort for the headline A rate, distribution, withdrawal rate and ease score; do not place a professor-only A rate beside a course-wide distribution without labeling and separating them. All headline raw counts remain unweighted and recency weighting stays disabled for this launch.

## CON-CALC-02: Reference cohort fallback chain
- source: docs/final-mvp-plan.md
- type: schema
- content: For professor-course history, first try other sections of the same course as the reference cohort; otherwise other courses in the subject; then the eligible institutional reference corpus. For a course-only cohort, start with other courses in its subject. Exclude the displayed cohort from the reference at every level. Require at least 60 eligible A-F reference outcomes for a reference mean. Keep zero-valued reference means valid. Version cohort boundaries and method settings.
- note: this chain supplies `mu` (the prior mean) only. ADR-02 and ADR-03 (locked) forbid any subject or global value becoming a displayed score. See INGEST-CONFLICTS.md INFO 2.

## CON-API-01: API and storage boundary contracts
- source: docs/final-mvp-plan.md
- type: api-contract
- content: Preserve the existing application stack and service boundaries. Add migrations for durable state; keep derived grade results computed or cached rather than treating a final score table as primary evidence. Grade analytics - observed buckets, independently nullable metrics/statuses, selected cohort, empirical reference metadata, named terms and methodology version. Search/detail API - new historical-grade-ease fields, A rate, observed withdrawal, section identity, freshness, source URLs, RMP link status and null-safe sorts/filters; keep aliases only as a documented short transition and never retain old blended semantics under the new label. Metadata - configured supported terms/campus/subjects, default registration term, coverage and last refresh information; historical-only terms should not automatically become selectable registration targets. Seat status - shared latest validated state, successful observation timestamp, status reason, polling cadence, refresh failure and source URL, plus an inexpensive endpoint for visible-page refresh if needed. Alert endpoints - create pending watch, confirm ownership, request management link, list/cancel/rearm authenticated watches, and a provider webhook only if required; public responses avoid email enumeration. RMP storage - curated verified/rejected/unknown identity mappings with audit fields and canonical URL. Worker storage - poll state/leases, opening events, subscribers/watches, hashed tokens, outbox/deliveries, job outcomes and heartbeat, with unique constraints preventing duplicate watches and deliveries. Update Python models, serializers, TypeScript types, real client, fixtures, UI and CLI consumers together. Configure allowed write methods and origins for alert endpoints and enforce private management authorization on the server.

## CON-OPS-01: Deployment topology
- source: docs/final-mvp-plan.md
- type: api-contract
- content: A suitable simple deployment is one API service plus one worker and PostgreSQL, with the built frontend served by the existing hosting arrangement. A PostgreSQL outbox can use row locking and `SKIP LOCKED` for concurrent job claiming. FastAPI response background tasks are not, by themselves, a persisted scheduler or delivery ledger. A full Redis/Celery platform is unnecessary unless measured requirements justify it. Use one email provider; prefer an already configured provider, otherwise Resend is a proposed simple default behind a replaceable transport. Sender-domain ownership and DNS setup are prerequisites.

## CON-NFR-01: Proposed acceptance budgets
- source: docs/final-mvp-plan.md
- type: nfr
- content: On the selected staging host - representative search p95 at or below 2 seconds at 20 concurrent users; interactive usable search within 3 seconds on the agreed mobile test profile; watched sections ordinarily observed within the validated 5-minute target; queue-to-provider acceptance within 60 seconds of a validated opening under normal operation. Measure and record results. These are engineering targets; do not promise upstream or inbox latency. Search currently computes candidate rankings before slicing pagination and repeatedly invokes course analytics - benchmark and batch work before launching broad term searches and do not assume a 50-row page limits backend work. Cache keys include data/method versions; seat freshness and watch processing cannot depend on stale ranking caches.
