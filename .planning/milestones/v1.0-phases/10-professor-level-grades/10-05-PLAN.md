<objective>
Compute the per-instructor breakdown for each section in both ranking paths, embed it in historical_analytics, and serve it through the existing API with no migration.

Purpose: REQ-PROF-01 and D-09..D-15 need instructor-level figures next to the course-wide history. Embedding the breakdown in the cached historical_analytics JSON means: no schema change and no deploy-ordering hazard (the deployed code ignores the extra key); no loading or error states in the UI; and the search path stays one cache read.
Output: breakdown builder and wiring in `src/easy_a/analytics/queries.py`, API models, cache and service plumbing, tests.

Transport decision (CONTEXT "Claude's Discretion"): embedded, not lazy. Only rows at or above the collapse cutoff plus the current instructor are serialized, which bounds the payload. Plan 10-08 measures the hosted search p95 and an ENC 1101 page size after rollout.

Collapse cutoff decision (CONTEXT discretion, UI-SPEC default): 15 effective grades. The current instructor is pinned even below 15 when they have any letter-grade history, so a student always sees their own section's instructor with an honest denominator.

The builder lives in queries.py, next to SectionHistoricalAnalytics and the existing _instructor_course_stats, so scoring and display share one instructor-stats implementation. That also keeps the tracer at five files: cache-vs-on-demand parity forces both paths to change in the same commit.
</objective>
