<objective>
Scale the proven per-subject ingestion unit from one subject (CHM, 06-01) to all ~212 Tampa
subjects, safely.

Two scaling gaps identified in 06-RESEARCH.md must be closed at the ORCHESTRATION layer without
touching production ingestion code: (1) `target_cli.py` wraps the whole target list in one DB
transaction, so a single transient failure at scale discards all prior work — fixed by invoking the
existing CLI once per subject (each its own process/transaction, blast radius 1-33 courses); (2) no
rate-limiting/retry/backoff exists anywhere in the codebase — fixed by deliberate pacing between
subject invocations in the orchestrator. Then, after an explicit operator go-live checkpoint (this
run issues ~2,800 bounded requests against live USF), execute the full-scale ingestion.

Purpose: turn the tracer's single-subject proof into full Tampa coverage without a
partial-run-corruption or over-fetch incident.

Output: `scripts/refresh_all_tampa.py` (resumable, paced orchestrator) + its unit test + an operator
runbook, and the fully ingested Tampa Spring 2027 universe in hosted Supabase.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell -> live USF endpoints (at volume) | ~2,800 bounded GET/POST requests cross here; volume is the risk, not surface |
| per-subject subprocess -> hosted Supabase | Each subject commits in its own transaction; a failure must not corrupt other subjects |
| USF HTML (all subjects) -> ingestion pipeline | Untrusted external HTML at ~29x prior volume |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Denial of Service | live USF catalog/schedule endpoints | high | mitigate | Deliberate pacing between subject invocations (--pace-seconds, default 2s) + bounded exact-match queries only + no crawling (D-08/D-09); blocking human-verify gate before the run |
| T-06-04 | Denial of Service | partial-run data corruption | high | mitigate | Per-subject process/transaction isolation (blast radius 1-33 courses) + resumable progress file; never one transaction over all ~1,402 targets (Pitfall 1) |
| T-06-05 | Denial of Service | untrusted HTML parsing at scale | medium | mitigate | One subject's parser exception (CatalogParseError/ScheduleIngestError) fails only that subprocess; the orchestrator records it and continues |
| T-06-02 | Tampering | non-Tampa/wrong-suffix rows at scale | high | mitigate | Unmodified Tampa scope + suffix guards run inside every per-course pass; validated in 06-03 |

_No package installs in this phase — no supply-chain (T-06-SC) checkpoint applies._
</threat_model>
