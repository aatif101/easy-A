<objective>
Rewrite the `GET /api/v1/rankings/search` body to read from `section_rankings` with sort, filter,
and pagination done in SQL over one page (D-06), joining live seat data at request time (D-08),
while keeping the response contract and every query parameter byte-identical (D-03). This removes
the confirmed N+1 (`_rank_candidate_sections` looping `rank_section()` per CRN) that caused the
~600s Supabase search.

Purpose: turn the search path from O(whole term) to O(one page), which is the direct fix for
REQ-PERF-01's latency target.
Output: a rewritten `search_rankings` route reading the cache + live seat join, and an automated
test proving ordering (incl. NULL seats), total/pagination consistency, filters, and the seat
three-tier fallback.
</objective>
