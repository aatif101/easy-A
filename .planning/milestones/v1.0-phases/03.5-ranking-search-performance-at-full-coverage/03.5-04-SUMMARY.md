# Phase 03.5 Plan 04: Cleanup cascade coverage for section_rankings Summary

## Performance

- **Duration:** ~20 min
- **Tasks:** 2 completed

## Accomplishments
- Extended the explicit-delete sequence in `clean_other_campus_sections` (`src/easy_a/refresh/cleanup.py`) to delete `section_rankings` rows tied to removed sections, before the `Section` delete — mirroring the existing SeatSnapshot/SectionInstructor/Syllabus pattern exactly (fourth table, same shape).
- Widened `_dependent_ids`'s type union and added `SectionRankingCache` to `_lock_candidate_dependencies`'s locking loop.
- Added `section_ranking_ids` to `_IdentitySnapshot` and a `"section ranking"` entry to `_verify_identities`'s expected/actual dicts, so a stale-cache regression now fails the same identity check that already guards the other three dependent tables.
- Added `tests/refresh/test_cleanup_cascade.py` (5 tests) proving: removed sections' cache rows are deleted; no orphaned cache row survives; Tampa-target cache rows are preserved; a cleanup run with no cache rows completes without an FK violation; and the identity check fails when a cache row is deliberately left behind (monkeypatched `_delete_ids` to skip `SectionRankingCache`, confirming `CleanupError` raises and matches `"section ranking"`).
