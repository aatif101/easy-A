<objective>
Introduce `sections.removed_at` end to end in the serving path: model, migration 0004 (plus the seat_snapshots latest-snapshot index from RESEARCH Pitfall 7, under the same single go-ahead), cache rebuild exclusion and stale-row deletion, `/section` and `/course` filters, and a schema guard the API and worker use at startup.

Purpose: REQ-SYNC-01 says sections absent from a sanity-checked sweep are marked removed and leave search. Every later sync plan writes or reads this column. The search route reads only `section_rankings`, so the cache must drop removed rows (the rebuild currently only upserts; it never deletes).
Output: migration 0004, model changes, schema guard, filtered cache/service, tests.

Reversibility (flagged, costly): once 0004 is applied to hosted Supabase and the worker writes marks, undoing it means a downgrade that discards every removal mark and makes removed sections searchable again. It stays gated behind the operator go-ahead in plan 09-14.
</objective>
