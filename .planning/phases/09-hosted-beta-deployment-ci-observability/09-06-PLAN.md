In metadata.py add route GET /sync-status (response_model SyncStatusResponse) taking DbSession and term with Query(pattern matching /coverage's). The handler:
  - Computes source = sync_source(term) and now = datetime.now(UTC), through a module-level now function the tests can monkeypatch.
  - Runs three queries: the latest IngestRun with status "succeeded" for that source (by finished_at, then id); the latest IngestRun of any status for that source (by started_at, then id); and the count of "failed" runs for that source with started_at in the last 24 h.
  - Derives cadence_seconds from windows.interval_for(now).
  - Sets stale_after_seconds to windows.stale_after_seconds(last_success_at or now, now).
  - Sets is_stale when last_success_at is None or now minus last_success_at exceeds stale_after_seconds.
  - Sets in_registration_window from windows.contains(now).
  - Takes last_error_kind, only when the latest run failed, from the text before the first colon of error_message when that token is in easy_a.sync.SYNC_ERROR_KINDS (the shared vocabulary from 09-03; do not redefine it), else "unexpected".
  - Takes last_records_failed from the latest run.
  - Normalizes timestamps to UTC (SQLite returns naive values; use the as_utc helper from easy_a.schedule.freshness).
  - Never includes error_message in the response.
Create tests/api/test_sync_status.py with the existing api_client fixture pattern:

  - An unknown prefix gives "unexpected".
  - Failures older than 24 h are not counted.
  - Runs of another source or term are ignored.
  - term=bad gives 422.</action>
