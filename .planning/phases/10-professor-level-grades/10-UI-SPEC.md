# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** One new block, "Instructors for this course", inside the existing
`web/src/components/RankingDetails.tsx` expanded panel (CONTEXT D-09), plus the small utilities it
needs in `web/src/utils/rankings.ts` and type additions in `web/src/types/rankings.ts`. No new
route, no new table column, no inline row stats, no cross-course professor page (deferred). It
inherits the **existing production design system** (Tailwind 3 tokens in
`web/tailwind.config.ts` and `web/src/styles.css`). It does NOT adopt the 2026-09-25 "Student guide"
sketch palette (`.planning/sketches/001-student-experience/`): that sketch is a later,
whole-app rebuild; Phase 10 must ship inside the app as it exists today and must not pre-empt it.

**Upstream sources used (nothing re-asked).** CONTEXT.md D-02, D-09..D-15 (locked); REQUIREMENTS.md
REQ-PROF-01 and PROJECT.md D-06/D-07/D-20 (denominator, term count, source, explicit unavailable
states, fallback is not course history); sketch 001 `UI-SPEC.md` "Evidence contract" item 4 (only show
an instructor-specific claim when identity mapping and evidence meet backend rules).

## Placement and Layout

Order inside the expanded `RankingDetails` panel (changes marked **NEW**):

1. Header (course, instructor, modality) — unchanged
2. `<dl>` course-wide stats (Easiness, W rate, Effective sample, Confidence, Score source) — unchanged
3. **NEW — Instructor block**, full width, directly under the course-wide stats so instructor
   figures read "next to the course-wide history" (REQ-PROF-01)
4. Seat observation + seat source — unchanged
5. Policy signals / General Education grid — unchanged

Block structure (top to bottom):

1. **Header row** — `flex items-center justify-between gap-2`: left = `h4.detail-heading`; right =
   the one `InfoTip`. The InfoTip MUST be the last item at the right edge. Reason: `InfoTip`'s
   tooltip is `w-64` anchored `right-0`, extending left from the button; a left-placed tip would be
   clipped off-screen at 320 px.
2. **Source line** — 12px stone-600 paragraph under the heading (copy below).
3. **Staff explainer** — only for Staff sections (copy below), 12px stone-600.
4. **Row list** — `ul` with `space-y-2` (8px between rows).
5. **"Show all" disclosure** — native `<details>` holding rows beyond the visible cap.
6. **Others line** — counts only, 12px stone-600.

Container: `section` with `className="mt-6"`, `aria-labelledby="{id}-instructors-heading"`. The block
heading id MUST be derived from the `id` prop of `RankingDetails` (`${id}-instructors-heading`),
because `RankingDetails` is rendered once in the desktop table and once in the mobile card list in the
same DOM; fixed ids would duplicate. Do not start any `aria-label` with "Details for" (existing tests
query `region` name `/^Details for/`).

Rows (`li`): `rounded-md border border-rule bg-white/70 p-3` — identical to the existing Policy
signal cards so the panel stays visually uniform. Single-column stack at all widths below `md`;
at `md` and up a row is two columns: identity + metrics on the left, score on the right
(`md:flex md:items-start md:justify-between md:gap-4`, score block `md:text-right md:shrink-0`).
Never a `<table>` and never horizontal scroll: this panel already sits inside an `overflow-x-auto`
wrapper on desktop.

### Visible cap and overflow

- Visible by default: the pinned current-instructor row (if any) plus the top rows by n, **maximum 5
  rows total**. Remaining qualifying rows go inside `<details>` with the summary
  `Show all {N} instructors` (N = total qualifying rows, including the visible ones). The summary
  text does not change when opened.
- Native `<details>/<summary>`: no JS state, works with the keyboard. Summary: `min-h-11` (44px),
  `cursor-pointer`, 14px bold spruce, `focus-visible:outline focus-visible:outline-2
  focus-visible:outline-offset-2 focus-visible:outline-spruce` (matches existing controls).
- If total qualifying rows ≤ 5, render no `<details>` at all.

## Row Content Contract

Line 1: **name** (14px bold ink, `break-words`, never truncated) followed by chips (wrapping,
`gap-2`), then on the pinned row the "This section" label.

Line 2 (metrics, 14px regular stone-700), the locked D-12 shape:

`{pct}% A · {n} grades · {k} term(s) ({first}–{last})`

e.g. `40% A · 175 grades · 3 terms (Spr 25–Spr 26)`

| Piece | Rule |
|-------|------|
| `{pct}% A` | A share of A–F letter grades, **rounded to a whole number** (D-12 example; avoids false precision at small n). Visible text is `40% A`; add `<span className="sr-only"> grades</span>` so a screen reader hears "40% A grades". |
| `{n} grades` | The instructor-course `effective_n`, rounded, plural-aware: `1 grade`, `175 grades`. This is the denominator (D-06). |
| `{k} term(s)` | Distinct grade terms behind the figure. `1 term`, `3 terms`. |
| `({first}–{last})` | Short term labels. Single term: `(Fall 25)`, no dash. Format: `Spr`/`Sum`/`Fall` + two-digit year; term code suffix `01` = Spr, `05` = Sum, `08` = Fall. Unknown suffix: fail closed to the raw code (e.g. `202603`). Add helper `formatTermShort(code)` to `utils/rankings.ts`. |
| Separators | `·` characters are wrapped in `<span aria-hidden="true">`. |

Score slot (right column at `md+`, below the metrics on phones):

| Row state | Score slot shows |
|-----------|------------------|
| Scored (n ≥ scoring minimum, default 30) | `Easiness` label (12px stone-600) over `7.2` (18px bold `font-display`, spruce) + ` / 10` (12px stone-600). This is the shrunk score used in scoring (D-12). |
| Below scoring minimum (listed because n ≥ collapse cutoff, default 15) | `Not scored` (14px bold stone-700) over `Under {N} grades` (12px stone-600), where N is the scoring minimum supplied by the API (never hard-coded in the frontend). No number is shown. |
| Pinned row, scored, and `ranking.score_source === "instructor_course"` | The scored slot plus 12px bold spruce line: `Used in this section's score`. |
| Pinned row, below scoring minimum | `Not scored` slot plus 12px stone-600 line: `Not used in this section's score. This section's score uses course-wide history.` |
| Staff section (any row) | Scores display as above, never accompanied by "Used in this section's score" (D-11). |

### Chips (D-15: only two kinds of per-row chip)

| Chip | Condition | Text | Style |
|------|-----------|------|-------|
| Single term | `term_count === 1` (flag only; score unchanged, D-02) | `Based on 1 term` | `rounded border border-amber-300 bg-amber-50 px-2 py-0.5 text-xs font-bold text-amber-950` (matches the existing amber "limited history" family) |
| Low sample | n below scoring minimum | `Limited sample` | same amber style |

No other per-row chip. The "This section" marker is a plain label (not a bordered chip):
12px bold spruce text `This section` (the highlight is also carried by background and left
border, below, so meaning is never color-only).

### Pinned (current-instructor) row

First in the list, never repeated further down. Highlight: `bg-moss/70 border-spruce/40 border-l-4
border-l-spruce` plus the `This section` label. Applies only when the section's instructor is a
named person (`instructorLabel(ranking)` returns a real name). For a Staff / ambiguous / unknown
instructor there is **no pinned row and no highlight** (D-10, D-11).

### Sorting, cutoff, "others"

- Sort by n descending; ties broken by name ascending (stable, deterministic).
- Collapse cutoff (planner confirms, default **15 grades**, CONTEXT discretion): instructors below
  it are not listed individually. They appear only in the Others line:
  `{M} other instructors with under {C} grades each` (singular: `1 other instructor with under {C}
  grades`). Counts only; no pooled A%, no pooled score, no names.
- A "Staff" or blank instructor is never a row and never counted in Others (D-08); those grades remain
  in the course-wide figures only.

panel title (not touched). 2 weights only in the new block: 400 and 700. Do not use
`font-semibold` or `font-extrabold` in the new block, and do not introduce `text-[11px]` (the
Phase 8 UI review flagged it; use 12px).

| Role | Size | Weight | Line Height |

The UI contract requires these facts per section's ranking detail. Naming and transport (embedded
in the search item vs. a lazy detail request) are CONTEXT "Claude's Discretion". If lazy, the
loading and error states in the copy table apply; if embedded, they do not render.

| Fact | Type | Notes |
|------|------|-------|

statistics (no pooling, no re-shrinkage, no ranking of professors against each other).

## Interaction and Accessibility

- Read-only block. Controls: the `InfoTip` (hover + keyboard focus; existing behavior) and the native
  `<details>` summary (Enter / Space). No click targets on rows; rows are not buttons or links.
- Tab order: InfoTip, then the disclosure summary. Nothing else in the block is focusable.
- The `<ul>` has no `role` override. The disclosure content stays in DOM order after the visible
  rows. Heading is an `h4` like its siblings; the block is a labelled `section` (landmark name e.g.
  "Instructors for this course").
- Reduced motion: no new transitions. The InfoTip already honors the global reduced-motion rule.
- Reflow: at 320px width the block is single-column; names and metrics wrap (`break-words`), no
  clipping, no horizontal scroll. The Others line and chips wrap.
- Contrast: all text ≥ 4.5:1 per the color rules above.
- Sync behavior: the pinned row follows the live section instructor (Phase 9 sync). If the current
  instructor changes while the panel is open, the pinned row updates with the next data refresh;
  no animation or toast.
