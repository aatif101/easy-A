<objective>
Build the one-off historical backfill (D-05..D-08): fetch the five grade terms with one whole-term request each, keep only rows that back a stored grade row, and write Section plus SectionInstructor rows idempotently, with a rolled-back dry-run mode that prints counts first.

Purpose: production has 0 sections for grade terms, so `_fetch_instructor_course_grade_observations` can never join (research report headline). Writing exactly the graded term+CRN rows (about 8.7k) activates the existing join with no query change.
Output: `src/easy_a/schedule/backfill.py`, `src/easy_a/schedule/backfill_cli.py`, `scripts/backfill_historical_sections.py`, tests.

The existing `_upsert_sections` is not reused: it appends a SectionInstructor and a SeatSnapshot on every run and does one SELECT per row. This plan writes in bulk, change-only, with no seat snapshots. Plan 10-06 later adds the D-04 what-if diff to `--dry-run`, the cache rebuild to `--apply`, and a rollback mode.
</objective>
