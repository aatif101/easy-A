<objective>
Establish the derived-cache spine end to end: a `section_rankings` table (ORM model + Alembic
migration), a refresh-time population function that computes each row by reusing `rank_section()`'s
existing scoring helpers, and a read/hydrate helper that reconstructs a `SectionRanking` from a
cached row plus a live seat join — proven byte-for-byte identical to on-demand `rank_section()` by
an automated parity test.

This is the TRACER for Phase 3.5: it wires DB schema -> refresh-time population -> cached read ->
parity verification in one thin slice (one course, happy path), so D-02's byte-for-byte parity —
the phase's central risk — is proven on the first commit before any expansion (route rewrite,
filters/sorts, refresh wiring, cleanup cascade, benchmark) builds on it.

Purpose: Precompute rankings so search never re-ranks the whole term (D-01), while guaranteeing the
cached numbers are exactly the current scoring model's output (D-02) and never bake in seat data
(D-08).
Output: `section_rankings` table, `refresh_section_rankings()`, a cache-row hydrate helper, and the
parity test that is the load-bearing acceptance control for the whole phase.
</objective>
